Project 1: Images of the Russian Empire

Colourising the Prokudin-Gorskii Photo Collection

Overview

Sergei Prokudin-Gorskii photographed the Russian Empire in the early 1900s by taking three black-and-white exposures of each scene through red, green, and blue filters. This project reconstructs color photographs from his glass plate scans by splitting each image into its B, G, R channel strips and automatically finding the (x, y) translation that best aligns G and R onto B.

Metrics

To score a candidate shift, I compared the shifted channel against the reference B channel with one of two metrics, computed only on the interior of the image. The outer 10% is cropped out before scoring, since the border of each scan often has scratches, dark spots, or folded edges that would otherwise pollute the score and pull the "best" shift toward matching border noise instead of actual image content.

L2 (sum of squared differences / Euclidean distance)

L2 = √( Σx,y ( I₁(x,y) − I₂(x,y) )² )

L2 is calculated by subtracting corresponding pixels, squaring the differences, summing them up, then square rooting it. Squaring makes large mismatches count disproportionately more than small ones, which makes L2 sensitive to precise pixel-level agreement. This is good for exact alignment, but it assumes the two channels are equally bright to begin with. When that assumption breaks (see emir.tif below), L2 can be misled by genuine color differences rather than misalignment. Lower L2 is better.

NCC (normalized cross-correlation)

NCC = (I₁ − mean(I₁))⁄‖I₁ − mean(I₁)‖  ·  (I₂ − mean(I₂))⁄‖I₂ − mean(I₂)‖

Each channel is mean-centered and scaled to unit norm before comparing, which removes each channel's own brightness and contrast from the comparison. What's left is a measure of whether the two channels' bright/dark patterns line up, which makes NCC more robust to channels that were genuinely exposed or colored differently. Higher NCC (closer to 1) is better.

Part 1: Single-Scale Alignment

Approach

For the low-resolution JPEG images, I implemented a naive exhaustive search over every integer (x, y) shift in a window of ±15 pixels, a 31×31 grid of 961 candidate shifts per channel. This range comfortably covers the true misalignment on these images (all well under 15 pixels), and since these images are small, brute-forcing all 961 combinations is fast enough to run in well under a second per channel. For each candidate shift, I use np.roll to translate the channel, crop both the shifted channel and the reference to their shared interior, and score the match with L2 or NCC as described above. Whichever shift produces the best score (lowest L2, or highest NCC) is kept as the final alignment for that channel, and G and R are each aligned to B independently.

Part 2: Multi-Scale Pyramid Alignment

Motivation

The large .tif scans are far too high-resolution for a ±15 pixel brute-force search, since true misalignment on these images ranges from about 15 pixels up to over 170 pixels (see melons.tif below), and searching a window that size exhaustively at full resolution would mean scoring hundreds of thousands of candidate shifts per channel, each over a multi-megapixel image. That's far too slow to be practical, so I implemented a coarse-to-fine image pyramid instead.

How the pyramid works, step by step

The core idea is to find a rough shift cheaply on a small version of the image, then use that rough answer to narrow down the search at each larger scale, rather than searching the full range at full resolution.

  1. Downsample. The image is shrunk by 2× repeatedly, using 2×2 block averaging, until it's smaller than a minimum size threshold.
  2. Base case. At the smallest scale, I run the same brute-force ±15 pixel search from Part 1 directly. Because the image is tiny at this point, this is fast, and because everything is shrunk proportionally, a small shift found here corresponds to a much larger shift at full resolution.
  3. Climb back up. At each larger scale, I take the shift found at the level below and double it (since the image just doubled in size, the correct shift should too), then run a small local search (±8 pixels) around that doubled estimate to correct for any rounding or averaging error introduced by downsampling.
  4. Repeat until back at full resolution, where the final refined shift is returned.

def downsample(im):
    h, w = im.shape[0] - im.shape[0] % 2, im.shape[1] - im.shape[1] % 2
    im = im[:h, :w]
    return (im[0::2, 0::2] + im[1::2, 0::2] + im[0::2, 1::2] + im[1::2, 1::2]) / 4.0

def align_pyramid(channel, base, window=15, min_size=400, metric='l2'):
    if min(channel.shape[0], channel.shape[1]) <= min_size:
        return align(channel, base, window=window, metric=metric)

    small_channel = downsample(channel)
    small_base = downsample(base)
    coarse_shift = align_pyramid(small_channel, small_base, window=window,
                                  min_size=min_size, metric=metric)
    dx, dy = coarse_shift[0] * 2, coarse_shift[1] * 2

    # refine with a small local search around the doubled estimate
    best_shift = (dx, dy)
    best_score = None
    edge = int(0.1 * min(channel.shape[0], channel.shape[1]))
    for ddx in range(-8, 9):
        for ddy in range(-8, 9):
            shift = (dx + ddx, dy + ddy)
            shifted = np.roll(channel, shift, axis=(0, 1))
            a = shifted[edge:-edge, edge:-edge]
            b = base[edge:-edge, edge:-edge]
            score, lower_is_better = score_shift(a, b, metric)
            better = (best_score is None) or (score < best_score if lower_is_better else score > best_score)
            if better:
                best_score = score
                best_shift = shift
    return best_shift

For images already smaller than the minimum size threshold (the JPEGs), this function skips the recursion entirely and falls straight through to the base case. Hence the same align_pyramid function handles both the small JPEGs and the large TIFFs, and reproduces the Part 1 results exactly on the former.

Problems Encountered & What I Changed

1. Pyramid made a small image worse

Once I switched cathedral.jpg over to the pyramid function, it came out worse than my original single-scale result. The image is small enough that the pyramid downsampled it once into a blurry, low-detail version, searched on that instead of the original, and only refined by ±2 pixels afterward, which was not enough to recover from a coarse-level mistake caused by the blur.

What I changed: I raised the pyramid's min_size threshold so small images like the JPEGs skip the recursion entirely and fall straight through to plain brute-force search at full resolution, matching the single-scale result exactly.

2. Emir.tif misaligned due to brightness mismatch between channels

Raw-pixel L2/NCC alignment produced a clearly doubled/ghosted result on emir.tif, visible as thick solid color bands rather than a sharp image. The robe's saturated blue and red dye is bright in one filtered exposure and dark in another. These are real color differences, not misalignment, so my metric was trying to match brightness patterns that were never going to agree.

What I changed: I aligned on image gradients (edge strength) instead of raw pixel brightness. Edges: the outline of the beard, robe folds, embroidery, are shared structure across all three channels even when raw brightness isn't, making the alignment far more robust to saturated color. The channel is still shifted and merged using the original pixel data; gradients are only used to score candidate shifts.

def gradient_magnitude(im):
    gx = np.zeros_like(im)
    gy = np.zeros_like(im)
    gx[:, :-1] = np.diff(im, axis=1)
    gy[:-1, :] = np.diff(im, axis=0)
    return np.sqrt(gx**2 + gy**2)

def align_gradient(channel, base, window=15, metric='l2'):
    gc = gradient_magnitude(channel)
    gb = gradient_magnitude(base)
    return align(gc, gb, window=window, metric=metric)
